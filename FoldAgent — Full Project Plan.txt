# FoldAgent — Full Project Plan + Todo List
## Open-source, local-first research coordination platform inspired by Paul Conyngham’s Rosie workflow

Date: 2026-04-16
Status: Planning / README draft
Scope: Research, clinical-review, and veterinary-oncology coordination software only.
Hard rule: This project must NOT provide DIY vaccine manufacturing, dosing, injection, administration, or self-treatment instructions.

---

# 1. Project Overview

FoldAgent is an open-source, local-first software platform for organizing the workflow around personalized cancer-vaccine research cases for dogs or humans.

The project is inspired by Paul Conyngham’s public story about using AI, sequencing, AlphaFold, and university scientific collaborators to help design an experimental personalized mRNA cancer treatment approach for his dog Rosie.

The goal is NOT to create a “make your own vaccine” app.

The goal is to build a serious, auditable, expert-supervised research workflow tool that:

1. Loads and organizes tumor/normal sequencing data.
2. Runs or coordinates standard bioinformatics pipelines.
3. Connects to multiple AlphaFold backends for protein-structure modeling.
4. Produces transparent candidate-antigen reports for expert review.
5. Surfaces uncertainty, validation gaps, and safety warnings.
6. Generates ethics/IRB/veterinary review documentation.
7. Helps coordinate licensed labs, oncologists, veterinarians, researchers, and sequencing providers.
8. Exposes plug-and-play agent skills for Claude Code, OpenClaw, and Hermes so agents can help manage paperwork, timelines, reporting, and technical workflow orchestration.

The system should treat every output as “research candidate information requiring professional review,” not as medical advice or an administerable treatment plan.

# 3. Core Product Definition

FoldAgent should be framed as:

A privacy-first research case manager and computational biology workflow orchestrator for personalized cancer-vaccine exploration under licensed professional supervision.

FoldAgent should NOT be framed as:

- A cure generator.
- A direct-to-consumer treatment app.
- A vaccine manufacturing guide.
- A replacement for veterinarians, oncologists, immunologists, regulatory review, IRB review, or licensed RNA manufacturing facilities.

# 4. System Modes

## 4.1 Dog / veterinary research mode

Purpose:
Support veterinary-oncology research coordination for canine cancer cases.

Requirements:
- Explicit vet-oncologist oversight required.
- Species-specific genome/reference configuration.
- DLA/MHC limitations clearly surfaced.
- Owner consent package.
- Veterinary ethics package.
- No self-administration workflow.
- No dosing instructions.
- No compounding or manufacturing instructions.

## 4.2 Human clinical-research mode

Purpose:
Support patient/clinician/research-team organization for clinical-trial style review.

Requirements:
- Human mode must be more restrictive than dog mode.
- Require physician/oncologist ownership of the case.
- Require IRB/ethics path before any downstream manufacturing discussion.
- Include clinical-trial matching.
- Include “not for treatment use” warnings on every generated output.
- No direct patient self-use workflow.
- No generated administerable construct.

## 4.3 Demo / education mode

Purpose:
Allow developers to test the app with public, synthetic, or toy datasets.

Requirements:
- Use synthetic variants by default.
- No real patient/pet data required.
- No treatment claims.
- Safe demo report showing pipeline mechanics only.

# 5. Safety Boundaries

FoldAgent may generate:

- Case organization summaries.
- Sequencing inventory.
- Variant tables.
- Candidate-antigen review reports.
- AlphaFold structure job manifests.
- Protein structure visualization links.
- Confidence and uncertainty reports.
- Missing-data checklists.
- Ethics/IRB/veterinary-review drafts.
- Lab outreach email drafts.
- Cost/timeline estimates.
- Audit logs.
- Agent task plans.
- Expert-review packets.

FoldAgent must NOT generate:

- DIY vaccine manufacturing protocols.
- Injection instructions.
- Dosing schedules.
- LNP formulation instructions.
- Tumor-lysate preparation instructions.
- Adjuvant mixing instructions.
- Sterility/QC release instructions for real administration.
- “Ready to inject” sequence packages.
- Medical recommendations to proceed with treatment.
- Claims that AI cured cancer.
- Claims that an output is clinically valid without professional validation.

Any module that touches mRNA sequence design must be locked behind:
- Expert mode.
- Local-only processing.
- Case owner verification.
- Required warning banner.
- Export label: “Research candidate only — not administerable.”
- Audit log entry.
- Approval checkpoint before export.

# 10. AlphaFold Backend Design

Goal:
Support all practical AlphaFold paths without locking the project to one version.

Backend interface:
- name
- version
- mode: local | cloud | mock
- requires_gpu
- requires_external_upload
- supports_protein_only
- supports_complexes
- supports_rna_dna_ligands
- license_notes
- run_structure_prediction(input_manifest)
- validate_environment()
- estimate_cost()
- estimate_runtime()
- collect_outputs()

Backends:

1. MockAlphaFoldBackend
- Used for tests and demo mode.
- No real biological prediction.
- Returns fixture PDB/mmCIF files.

2. ColabFoldBackend
- Default MVP backend.
- Practical local/Colab pathway.
- Lower setup burden than full AlphaFold 2.
- Good for development and demos.

3. LocalColabFoldBackend
- Local install pathway.
- Good for users with local GPU.
- Must clearly disclose when remote MSA servers are used.

4. AlphaFold2LocalBackend
- Official AlphaFold 2 local backend.
- Heavy storage and setup.
- Requires large sequence databases.
- Theoretical modeling only.

5. AlphaFold3LocalBackend
- Official AlphaFold 3 inference backend.
- Requires source install and model-parameter access under Google terms.
- Better future support for biomolecular complexes.
- Must track allowed use and license restrictions.

6. AlphaFoldServerBackend
- Cloud/manual fallback.
- Useful for users without GPU.
- Must warn about privacy and external upload.
- Should not silently upload private genomic/protein data.

Backend selector config:

alphafold:
  default_backend: colabfold
  allowed_backends:
    - mock
    - colabfold
    - local_colabfold
    - alphafold2_local
    - alphafold3_local
    - alphafold_server
  cloud_upload_requires_confirmation: true
  cache_outputs: true
  store_confidence_metrics: true

# 11. Agent Skill Packs

Goal:
Make the project plug-and-play with Claude Code, OpenClaw, and Hermes.

Shared principle:
Each skill is a folder containing SKILL.md plus optional scripts/resources.

Skill pack names:

1. run_full_foldagent_case_review
Purpose:
Run the safe end-to-end case-review workflow:
- preflight
- data inventory
- pipeline status
- candidate report
- safety gates
- export expert-review packet

2. organize_case_data
Purpose:
Organize uploaded sequencing files, checksums, metadata, sample types, and missing-data issues.

3. run_bioinformatics_pipeline
Purpose:
Trigger approved local wrappers for alignment, variant calling, annotation, and candidate prioritization.
Must not output treatment instructions.

4. get_alphafold_structures
Purpose:
Queue and retrieve structure jobs across configured AlphaFold backends.

5. generate_candidate_review_report
Purpose:
Create a transparent candidate-antigen report for expert review.
Must include uncertainty, model limits, and “not administerable” labels.

6. create_ethics_review_package
Purpose:
Draft IRB/veterinary ethics package, consent forms, data-use language, risk summaries, and oversight checklist.

7. coordinate_licensed_lab_outreach
Purpose:
Draft emails and checklists for contacting sequencing providers, veterinary oncologists, university RNA institutes, or clinical collaborators.
Must not provide manufacturing steps.

8. monitor_case_progress
Purpose:
Track appointments, imaging dates, professional review status, lab status, adverse-event notes entered by professionals, and report updates.

9. autoresearch_optimize_software_pipeline
Purpose:
Use Karpathy autoresearch only to improve software metrics:
- report completeness
- false-positive flagging
- test coverage
- runtime
- UI clarity
- documentation quality
Not allowed:
- autonomous wet-lab optimization
- autonomous treatment design
- autonomous sequence optimization for administration

# 12. What Is Missing From the Pasted Draft and How This Plan Fixes It

Problem 1:
The earlier plan blurred “vaccine design” and “clinical use.”

Fix:
This plan separates computational candidate review from manufacturing/treatment. No ready-to-administer outputs.

Problem 2:
Paul’s public GitHub repo was treated like the exact Rosie mRNA pipeline.

Fix:
This plan labels it correctly as related direct source material, not the exact mRNA pipeline.

Problem 3:
Regulatory bottlenecks were underweighted.

Fix:
Ethics/IRB/veterinary review is a core phase, not a stretch goal.

Problem 4:
Human and dog workflows were mixed.

Fix:
Separate dog mode, human clinical-research mode, and demo mode.

Problem 5:
AlphaFold version support was vague.

Fix:
Use a backend abstraction supporting ColabFold, LocalColabFold, AlphaFold 2, AlphaFold 3, AlphaFold Server, and mock backends.

Problem 6:
Agent integration was not plug-and-play enough.

Fix:
Create actual skill packs for Claude Code, OpenClaw, and Hermes using SKILL.md folders.

Problem 7:
Safety gates were not explicit.

Fix:
Add hard “must not generate” boundaries, audit logs, approval checkpoints, and export labels.

Problem 8:
No source registry.

Fix:
Create docs/source_registry.md with direct Paul links, reporting links, tool links, and status notes.

Problem 9:
No error logging plan.

Fix:
Add structured logs, per-case audit logs, task logs, failed-tool diagnostics, and reproducibility metadata.

Problem 10:
Autoresearch was too broad.

Fix:
Limit autoresearch to software improvements and measurable non-clinical metrics.

- A user can create a demo case.

# 16. Risks and Mitigations

Risk:
Users mistake the tool for a cure generator.

Mitigation:
Persistent warnings, blocked outputs, expert-review labels, no treatment instructions.

Risk:
AI hallucination creates false confidence.

Mitigation:
Source registry, citations, model/version appendix, uncertainty flags, expert-review workflow.

Risk:
AlphaFold output is treated as clinical validation.

Mitigation:
Structure predictions labeled as theoretical modeling only.

Risk:
Private genomic data is leaked.

Mitigation:
Local-first defaults, encryption, external-upload gates, redaction, audit logs.

Risk:
Agent skills take unsafe autonomous actions.

Mitigation:
Dry-run defaults, approval gates, unsafe-output scanner, audit logs, limited permissions.

Risk:
Human and veterinary workflows get confused.

Mitigation:
Separate modes, separate templates, separate warnings.

Risk:
Paul’s direct GitHub protocol is misused.

Mitigation:
Link as source/context only. Do not copy operational lab protocol steps into FoldAgent.

Risk:
Regulatory constraints are underestimated.

Mitigation:
Ethics/IRB/veterinary review is a first-class workflow.

Risk:
Autoresearch optimizes the wrong thing.

Mitigation:
Restrict autoresearch to software metrics and synthetic demos.
